Update `xrspatial.zonal.hypsometric_integral` so it validates raster inputs before computing. Users calling `hypsometric_integral()` with a 2D `xarray.DataArray` `values` raster whose dtype is complex or non-numeric should receive a `ValueError` indicating that `values` must have a real numeric dtype, rather than getting a coerced numeric result. Invalid `zones` or `values` inputs that are not valid 2D rasters should be rejected during validation before computation, while valid 2D real numeric `zones` and `values` inputs should continue to return the same hypsometric integral result as before.
