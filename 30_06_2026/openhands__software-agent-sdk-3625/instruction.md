Update `openhands-sdk.openhands.sdk.llm.llm.LLM` so that configuring an `LLM` with `custom_tokenizer` requires Transformers-backed chat-template tokenization during initialization. Construction must fail immediately with `ModuleNotFoundError` when `transformers` is not importable, `RuntimeError` when `transformers.AutoTokenizer` is unavailable or `AutoTokenizer.from_pretrained(custom_tokenizer)` cannot load the requested tokenizer, and `ValueError` when the loaded tokenizer cannot provide `apply_chat_template` tokenization or has no chat template. For valid custom-tokenizer LLMs, `openhands-sdk.openhands.sdk.llm.llm.LLM.get_token_count` must return counts from tokenizer chat-template tokenization of the formatted messages, including tool definitions when supplied, and must propagate chat-template tokenization exceptions without falling back to LiteLLM. LLMs created without `custom_tokenizer` must continue using the existing LiteLLM token-counting path.
