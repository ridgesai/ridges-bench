In xrspatial.proximity, repeated calls to xrspatial.proximity.proximity on numpy-backed input using the line-sweep path must preserve the same Euclidean and Manhattan proximity distance values while avoiding fresh kernel compilation on every call. After the first call compiles a needed argument-type signature, later calls in the same Python process with matching argument types must reuse it for both default/Euclidean calculations via xrspatial.proximity.euclidean_distance and Manhattan calculations via xrspatial.proximity.manhattan_distance. The same reuse behavior must apply when xrspatial.proximity.proximity is evaluated through dask-backed numpy chunks on the bounded line-sweep path in a warm worker process.
