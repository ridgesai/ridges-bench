Update `optype.infer.infer` so inferred union types are simplified by runtime subtype relationships. From a user's perspective, a generator that can yield both `True` and `1` should render as `() -> Generator[int]` because `bool` is a runtime subtype of `int`; any inferred union containing a runtime subclass and its superclass should render only the superclass for that relationship. Do not apply PEP 484 numeric tower promotion: unrelated runtime types such as `int` and `float` must remain distinct and render as `int | float`, not as `float` or `complex`.
