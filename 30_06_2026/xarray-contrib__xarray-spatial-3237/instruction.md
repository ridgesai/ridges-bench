Fix `xrspatial.geotiff._writers.eager.to_geotiff` so that `to_geotiff(data, path, pack=True)` on dask-backed data being restored to an integer GeoTIFF dtype with scale/offset metadata and no nodata sentinel does not eagerly scan the full dask graph for NaN pixels at call time. Clean dask-backed inputs should compute each source chunk only as part of the pack/write operation and write the same packed raster values and relevant packing metadata as the equivalent numpy-backed path. Dask-backed inputs containing NaN pixels in this no-sentinel integer restoration case should not raise from `to_geotiff` itself; they should raise the same `ValueError` when the write computation reaches the affected chunk. Numpy-backed inputs in the same NaN/no-sentinel case must keep the existing eager call-time `ValueError` indicating integer dtype restoration cannot proceed because NaN pixels are present and no nodata sentinel is declared.
