Fix `xrspatial.proximity.allocation` and `xrspatial.proximity.direction` in the `xrspatial.proximity` module so Dask-backed rasters processed through the KDTree proximity paths resolve equidistant target ties the same way as NumPy-backed rasters. When a tied output pixel is equidistant from targets in different chunk columns, the winning target must be the one with the lowest global row-major flat index, independent of chunk-column layout; `allocation` must return that target’s value, such as `out.data.compute()[2, 3] == 2.0` for the issue repro, and `direction` must return the direction to that same selected target for the same raster and parameters.
