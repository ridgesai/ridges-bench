Fix `xrspatial.geotiff.open_geotiff` so eager GeoTIFF reads with `masked=True` on integer rasters match chunked/lazy masking semantics for in-range nodata sentinels. The public function `xrspatial.geotiff.open_geotiff` must return `float64` data whenever the integer nodata sentinel is representable in the source dtype, even if no source pixel equals it; in that case all values remain finite and `nodata_pixels_present` is false when exposed. For `int64` and `uint64` rasters whose nodata is the dtype maximum, only source pixels exactly equal to that sentinel become `NaN`, while nearby valid values below the sentinel remain finite even if they share the same `float64` representation. For 64-bit integer nodata values above `2**53`, eager and lazy reads must expose the same `float64` dtype and identical `NaN` mask pattern.
