Fix GeoTIFF band-subset packing round trips through `xrspatial.geotiff.open_geotiff` and `xrspatial.geotiff.to_geotiff`. When a multiband GeoTIFF with distinct per-band `SCALE` or `OFFSET` metadata is opened as a band subset with `open_geotiff(..., unpack=True, band=...)` and then written with `to_geotiff(..., pack=True)`, the packed output must carry scale/offset metadata for the subsetted output bands, so reopening it with `open_geotiff(..., unpack=True)` or `open_geotiff(..., unpack=True, band=0)` returns the same unpacked numeric values as the original subset and does not raise `MixedBandMetadataError` from stale source-band metadata. For example, raw value `50` selected from a band with scale `0.2` must reopen as `10.0`, not as a value unpacked with another band's scale, and the selected band's offset must be preserved the same way. Data with only dataset-level `SCALE`/`OFFSET` metadata must continue to round trip normally through packed writes and unpacked reads.
